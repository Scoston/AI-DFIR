# AI-DFIR Fleet Attestation v0.5 — Deployment Runbook

## Purpose

v0.5 turns v0.4's investigator-run model-integrity framework into a continuous fleet control.

Each inference worker can continuously attest:

```text
model content
model manifest
activation fingerprint/reference
runtime hook inventory
adapter state
chat template/tokenizer
container image
delegated authority policy
tool schema
retrieval configuration
live activation chain
hardware attestation state
```

The central collector verifies signed heartbeats, rejects replay/out-of-order events, evaluates approved policy, tracks drift state, records alerts, and exposes fleet status/Prometheus metrics.

## State model

```text
NORMAL
  |
  +-- medium finding --> OBSERVE
  +-- high finding   --> ALERT
  +-- critical       --> CRITICAL

CRITICAL/ALERT/OBSERVE
  |
  +-- N consecutive clean heartbeats
  v
RECOVERED
  |
  +-- next clean heartbeat
  v
NORMAL

heartbeat overdue --> STALE
never reported     --> NEVER_SEEN
```

Recovery hysteresis prevents one transient clean heartbeat from instantly erasing an active incident state.

```bash

  --private /etc/ai-dfir/collector_ed25519.pem \
```

# 4. Create a node identity

On each model worker:

```bash
python fleet_crypto.py keygen \
  --private /etc/ai-dfir/node_ed25519.pem \
  --public /etc/ai-dfir/node_ed25519.pub.pem
```

Each node gets an independent identity.

Compromise or revocation of one node does not require replacing every fleet identity.

## Tiered checkpoint integrity

A 27B BF16 checkpoint is large. v0.5 does not re-read the entire model every few minutes.

Every heartbeat performs a fast metadata-tree measurement:

```text
relative path
file size
mtime
```

The agent performs a full SHA-256 content-tree calculation when:

```text
first enrollment
OR metadata changes
OR full_hash_interval_seconds expires
```

Default suggested full-hash cadence:

```text
24 hours
```

Tune this to the storage/performance characteristics of the deployment.

# 6. Generate the approved observed state

On a known-good node:

```bash
python fleet_agent.py \
  --config /etc/ai-dfir/fleet_agent.json \
  --dry-run > /tmp/approved_heartbeat.json
```

Dry-run:

- measures the node,
- signs the proposed heartbeat,
- does not contact the collector,
- does not increment persistent heartbeat state.

# 7. Build the node policy

```bash
python fleet_policy_builder.py \
  --heartbeat-envelope /tmp/approved_heartbeat.json \
  --expected-heartbeat-seconds 300 \
  --high-robust-z 5 \
  --critical-robust-z 10 \
  --recovery-heartbeats 3 \
  --out /tmp/node_policy.json
```

Review it before enrollment.

The policy includes approved:

```text
model manifest hash
model content-tree hash
fingerprint hash
approved-activation hash
runtime-inventory hash
container digest
chat-template hash
tokenizer hash
delegated-authority policy hash
tool-schema hash
```

For hardware-enforced fleets add:


# 9. Start the collector

Lab HTTP:

```bash
python fleet_collector.py \
  --registry /etc/ai-dfir/fleet_registry.json \
  --db /var/lib/ai-dfir/fleet.db \
  --host 127.0.0.1 \
  --port 8787 \
  --collector-private-key /etc/ai-dfir/collector_ed25519.pem
```

Production TLS:

```bash
python fleet_collector.py \
  --registry /etc/ai-dfir/fleet_registry.json \
  --db /var/lib/ai-dfir/fleet.db \
  --host 0.0.0.0 \
  --port 8787 \
  --collector-private-key /etc/ai-dfir/collector_ed25519.pem \
  --tls-cert /etc/ai-dfir/tls/server.crt \
  --tls-key /etc/ai-dfir/tls/server.key
```

Optional mTLS:

```bash
--client-ca /etc/ai-dfir/tls/client-ca.pem
```

A signed heartbeat provides evidence authenticity. TLS/mTLS provides transport confidentiality and an additional network-authentication layer. Use both where appropriate.

One measurement:

```bash
python fleet_agent.py \
  --config /etc/ai-dfir/fleet_agent.json \
  --once
```

Continuous:

```bash
python fleet_agent.py \
  --config /etc/ai-dfir/fleet_agent.json
```

A successful node heartbeat contains:

```text
node ID
monotonic sequence number
UTC timestamp
previous-heartbeat hash
node signature

approved-state measurements
activation-divergence summary
live-attestation chain state
hardware-attestation state
quick/full model-integrity measurements
```

The collector rejects:

```text

invalid signature
wrong key ID
payload-digest mismatch
clock-skew violation

```

# 11. Signed collector receipts

If the collector has `--collector-private-key`, it signs a receipt containing:

```text
node
sequence
accepted heartbeat SHA-256
collector receipt time
evaluated fleet state
findings
```

Configure:

```json
{
  "collector_public_key": "/etc/ai-dfir/collector_ed25519.pub.pem",
  "require_signed_collector_receipt": true
}
```

The node verifies the signature before advancing its local heartbeat state.

Receipts are preserved under the configured `receipt_dir`.

# 12. Continuous activation canaries

Build the approved runtime baseline from multiple clean executions using v0.4's baseline engine.

Then schedule:

```bash
python canary_runner.py \
  --model /srv/models/qwen38 \
  --fingerprint /opt/ai-dfir/fingerprint \
  --approved-activations /opt/ai-dfir/approved_activations \
  --baseline /opt/ai-dfir/approved_runtime_baseline.json \
  --prompts prompts/activation_probe.jsonl \
  --out /var/lib/ai-dfir/canary
```

The fleet agent reads:

```text
/var/lib/ai-dfir/canary/score/divergence_report.json
```

and includes the current divergence score in the next signed heartbeat.

An example hourly `systemd` timer is included under:

```text
deploy/systemd/
```

# 17. Delegated-authority drift

An agent can become more dangerous without changing its model.

v0.5 therefore hashes:

```text
authority_policy_file
tool_schema_file
retrieval_config_file
```

Example:

```text
Approved:
agent can READ account state

Suspect:
agent can READ + DISABLE account
```

If the authority-policy artifact changes:

```text
DELEGATED_AUTHORITY_DRIFT
severity: CRITICAL
```

This treats effective authority as part of model integrity.

# 19. Incident snapshot

When a node enters ALERT/CRITICAL, create a lightweight signed snapshot:

```bash
python fleet_snapshot.py \
  --case-id CASE-001 \
  --node-id qwen-prod-01 \
  --seq 4382 \
  --private-key investigator_ed25519.pem \
  --artifact live=/var/log/ai-dfir/live \
  --artifact runtime=/var/lib/ai-dfir/model_runtime_inventory.json \
  --artifact canary=/var/lib/ai-dfir/canary \
  --material deployed_manifest=/var/lib/ai-dfir/deployed_manifest.json \
  --out /evidence/CASE-001/fleet_snapshot
```

The snapshot uses references/digests rather than copying a 55 GB model into every alert package.

# 21. Threat model limitations

## Root compromise

An attacker with root/control of the inference worker may be able to:

```text
disable the local agent
forge local runtime files before measurement
interfere with instrumentation
prevent network delivery
```

Mitigations:

```text
independent node signing key protection
mTLS
external collector
hardware attestation
external eBPF/host telemetry
stale-heartbeat detection
remote signed receipts
remote/WORM evidence export
```

## Collector compromise

The collector should not possess node private keys.

Node signatures remain independently verifiable even if the central database is later compromised.

Back up:

```text
registry
node public keys
collector receipts
collector database
evidence bundles
```

to a separate trust domain.

## Fleet heartbeat is not a complete inference transcript

The heartbeat is a summarized integrity statement.

Use v0.4 live activation evidence, agent/tool trace, forensic replay, and signed case bundles for incident-level reconstruction.

# 22. Recommended production architecture

```text
                    SECURITY TRUST DOMAIN

             +----------------------------+
             | AI-DFIR Fleet Collector    |
             |                            |
             | signature verification     |
             | anti-replay                |
             | policy evaluation          |
             | SQLite / SIEM export       |
             | Prometheus / OTel          |
             +-------------+--------------+
                           ^
                           | TLS/mTLS
                           | signed heartbeat
                           | signed receipt
        +------------------+------------------+
        |                  |                  |
  +-----+------+     +-----+------+     +-----+------+
  | AI Worker 1 |     | AI Worker 2 |     | AI Worker N |
  |             |     |             |     |             |
  | node key    |     | node key    |     | node key    |
  | model hash  |     | model hash  |     | model hash  |
  | hooks       |     | hooks       |     | hooks       |
  | adapters    |     | adapters    |     | adapters    |
  | activation  |     | activation  |     | activation  |
  | authority   |     | authority   |     | authority   |
  +-------------+     +-------------+     +-------------+
```

The collector should ideally sit in a security-controlled trust domain separate from the inference workers.
