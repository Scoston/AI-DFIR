# AI-DFIR v1.6 Runbook — Production Assurance & Hardened Enterprise Deployment

## Quick validation

```bash
python scripts/release_check.py --quick
```

Full regression:

```bash
python scripts/release_check.py --full
```

Focused production suite:

```bash
python v16_selftest.py --out /tmp/aidfir-v16
```

## Production-control tools

```text
platform_assurance_v16.py        continuous health of the forensic platform
provider_certification_v16.py    expiring provider/API adapter certification
environment_separation_v16.py    lab/staging/production boundary validation
chaos_validation_v16.py          validate controlled failover drill results
release_integrity_v16.py         checksums / manifest / SBOM / provenance structure
security_assurance_v16.py        independent assessment freshness/scope gate
upgrade_assurance_v16.py         backup/migrate/verify/rollback gate
network_policy_validation_v16.py static Kubernetes hardening validation
schema_migration_v16.py          transactional checked migrations
production_readiness_v16.py      final evidence-backed production gate
enterprise_v16_analyze.py        attach production-assurance findings to a case
```

## Environments

Validate unique trust domains/resources:

```bash
python environment_separation_v16.py \
  --config config/environments.json \
  --out environment_separation.json
```

## Kubernetes

Production chart:

```text
deploy/kubernetes/helm/ai-dfir/
```

It assumes external HA PostgreSQL, KMS/HSM, IdP/SPIFFE and immutable evidence
storage. Those are deliberately not embedded into the application chart.

Render and validate using your organization Helm tooling, then run:

```bash
python network_policy_validation_v16.py \
  deploy/kubernetes/policies/hardening.yaml \
  --out network_policy_validation.json
```

## Schema migrations

Reference SQLite:

```bash
python schema_migration_v16.py \
  --migrations migrations/sqlite \
  --sqlite /var/lib/ai-dfir/reference.db
```

PostgreSQL:

```bash
python schema_migration_v16.py \
  --migrations migrations/postgres \
  --dsn "$AI_DFIR_POSTGRES_DSN"
```

Migration checksums are retained. A previously applied migration whose content
changes is rejected.

## Provider certification

A provider adapter is not "certified" simply because its code exists.
Generate receipts in staging against the organization/provider configuration for:

```text
authentication
pagination
rate_limit_recovery
time_window
schema_normalization
evidence_gap_reporting
negative_permission_case
```

Then:

```bash
python provider_certification_v16.py \
  --profile config/provider_certifications/openai.example.json \
  --receipts provider_test_receipts.json \
  --out provider_openai_certification.json
```

## Chaos/failover

Execute controlled drills with your infrastructure tooling. Feed the results to:

```bash
python chaos_validation_v16.py \
  --results chaos_results.json \
  --policy config/chaos_policy.json \
  --out chaos_validation.json
```

AI-DFIR does not initiate destructive chaos.

## Security assessment

Record independent assessment metadata and evaluate:

```bash
python security_assurance_v16.py \
  --report independent_security_assessment.json \
  --policy config/security_assurance_policy.json \
  --out security_assurance.json
```

## Release trust

Offline release verification:

```bash
python release_integrity_v16.py \
  --root ./release-assets \
  --checksums ./release-assets/SHA256SUMS \
  --manifest ./release-assets/PACKAGE_MANIFEST_V1.6.json \
  --sbom ./release-assets/SBOM_CYCLONEDX_1.7.json
```

Use Sigstore/SLSA tooling in CI/admission for cryptographic provenance identity.

## Final production gate

```bash
python production_readiness_v16.py \
  --config config/production_readiness_v16.example.json \
  --out production_readiness_v16.json
```

Do not bypass a failing gate by editing the JSON result. Fix or independently
waive the failed control under your organization's documented risk process.
