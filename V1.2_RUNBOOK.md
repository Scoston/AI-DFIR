## 4. Compare what the AI reads with what the human sees

Obtain an independent visible representation.

For example, an enterprise imaging service or validated rendering/vision
pipeline can create:

```text
visible_text.txt
```

The ordinary parser can create:

```text
machine_text.txt
```

Compare:

```bash
python representation_differential.py \
  --machine machine_text.txt \
  --visible visible_text.txt \
  --machine-source "document parser vX" \
  --visible-source "independent rendering pipeline vY" \
  --out representation_differential.json
```

AI-DFIR itself does not require OCR and does not treat OCR as unquestionable
ground truth. The independent representation and its provenance are evidence.

## 10. Signed session-history state

```bash

  --private session.pem \
  --public session.pub.pem
```

Checkpoint:

```bash
python session_state_integrity.py checkpoint \
  --session session.jsonl \
  --private-key session.pem \
  --out session.checkpoint.json
```

Verify later:

```bash
python session_state_integrity.py verify \
  --session session.jsonl \
  --checkpoint session.checkpoint.json \
  --public-key session.pub.pem \
  --out session_state_integrity.json
```

The analysis identifies the first line-hash divergence and highlights later
authorization/approval semantics as triage leads.

## 13. Signed acquisition manifest

Create collector key:

```bash
python fleet_crypto.py keygen \
  --private collector.pem \
  --public collector.pub.pem
```

Create:

```bash
python acquisition_manifest_v12.py create \
  --case-id CASE-001 \
  --case-root /evidence/CASE-001 \
  --collector-id collector-17 \
  --private-key collector.pem \
  --out acquisition.dsse.json \
  --source-type endpoint \
  --source-host host-17 \
  --source-user user-a \
  --clock-offset-ms -12 \
  --clock-uncertainty-ms 8 \
  --authoritative \
  --file 'session.jsonl=/evidence/CASE-001/session.jsonl'
```

Verify:

```bash
python acquisition_manifest_v12.py verify \
  --manifest acquisition.dsse.json \
  --public-key collector.pub.pem \
  --case-root /evidence/CASE-001 \
  --trust-out /evidence/CASE-001/ACQUISITION_TRUST.json
```

After successful verification the tool writes the verified manifest payload to:

```text
ACQUISITION_MANIFEST.json
```

Evidence quality can then promote a validated artifact to AUTHORITATIVE or
CORRELATED.

## 14. Optional semantic verdict

AI-DFIR does not automatically send quarantined content to an LLM.

If an isolated classifier is used elsewhere, return only:

```json
{
  "source_sha256": "...",
  "verdict": "malicious",
  "confidence": 0.93,
  "categories": ["prompt injection"],
  "classifier": "isolated-classifier",
  "classifier_version": "..."
}
```

Validate:

```bash
python semantic_verdict_ingest.py \
  --source quarantined_document.txt \
  --result classifier_result.json \
  --out semantic_verdict.json
```

Executable fields such as tool calls, commands, raw prompts or instructions are
rejected.

## 17. Evidence-quality hardening

v1.2 changes the default:

```text
mandatory evidence
    -> must have an acquisition SHA-256
```

An Evidence Pack may explicitly use:

```json
{"allow_unhashed": true}
```

only where that is justified.

Authoritative/corroborated flags are claims until the signed acquisition trust
record is verified.

## 19. Important interpretation rule

These propositions are separate:

```text
hidden/deceptive representation exists
AI consumed that representation
agent behavior changed
action occurred
action caused impact
attack tool can be attributed
```

Do not attribute EvilFontTool merely because a document contains unusual fonts.

Use generic mechanism evidence first and tool-specific indicators second.
