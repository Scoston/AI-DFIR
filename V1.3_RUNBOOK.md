# AI-DFIR v1.3 Runbook — A2A Identity & Signed Agent Cards

## 1. Install

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

`rfc8785` is the preferred RFC 8785 canonicalization implementation.

If it is unavailable, AI-DFIR can use the bundled Node.js canonicalizer.
It never silently substitutes ordinary `json.dumps()` for JCS.

# 2. Build an A2A trust store

Create:

```bash
python a2a_trust_store.py init \
  --out a2a_trust_store.json
```

Acquire a JWKS through an approved/forensic collection process and preserve its
SHA-256, retrieval time, DNS/TLS evidence and source URL.

Import:

```bash
python a2a_trust_store.py import-jwks \
  --store a2a_trust_store.json \
  --jwks captured_jwks.json \
  --source-url https://agent.example/.well-known/jwks.json \
  --provider-org "Example Corp" \
  --provider-url https://example.com \
  --allowed-origin https://agent.example \
  --assurance ENTERPRISE_PINNED \
  --out a2a_trust_store.updated.json
```

Create an AI-DFIR trust-store signing key:

```bash
python fleet_crypto.py keygen \
  --private a2a_trust_signer.pem \
  --public a2a_trust_signer.pub.pem
```

Sign the store:

```bash
python a2a_trust_store.py sign \
  --store a2a_trust_store.updated.json \
  --private-key a2a_trust_signer.pem \
  --out a2a_trust_store.signed.json
```

# 3. Verify a received Agent Card

```bash
python a2a_agent_card_crypto.py verify \
  --card received_agent_card.json \
  --trust-store a2a_trust_store.signed.json \
  --trust-public-key a2a_trust_signer.pub.pem \
  --out a2a_agent_card_verification.json
```

The verifier checks:

```text
A2A v1.0 canonicalization pre-processing
RFC 8785 JCS
RFC 7515 JWS

alg
typ
kid
critical headers
b64 behavior

ES256
RS256
PS256
EdDSA / Ed25519

JWK use / key_ops / alg restrictions
key revocation
key not-before
key expiry

provider organization binding
provider URL binding
interface-origin binding
jku source binding

minimum valid signatures
minimum trusted signatures
```

Output separates:

```text

trusted
policy_satisfied
```

# 4. Why `jku` is not automatically fetched

The A2A specification allows a JWS protected header to identify a JWKS URL.

AI-DFIR deliberately does not automatically fetch it during forensic
verification.

Instead:

```text
jku
  |
  v
compare with approved captured key-source URL
```

This avoids:

```text
attacker-controlled URL
       |
       v
forensic verifier performs network request
       |
       v
SSRF / trust bootstrap / evidence mutation
```

Fetch/capture JWKS separately using controlled enterprise collection.

# 5. Sign an internal/testing Agent Card

For an organization validating its own A2A deployment:

```bash
python a2a_agent_card_crypto.py sign \
  --card unsigned_agent_card.json \
  --private-key agent_es256.pem \
  --kid agent-key-2026-08 \
  --alg ES256 \
  --jku https://agent.example/.well-known/jwks.json \
  --out signed_agent_card.json
```


# 10. Analyst interpretation

Avoid:

> The Agent Card signature was valid, so the agent was trusted.

Prefer:

> The Agent Card JWS was cryptographically valid under key K. At the incident
> time, K was present in the signed enterprise trust store, was not expired or
> revoked, and its provider/interface bindings matched the received card.
> Transport evidence independently authenticated the A2A session, and execution
> records show the task remained within the card's declared skill and delegated
> authority.

Or:

> The Agent Card signature was cryptographically valid, but the key was no
> longer trusted because it had been revoked before the observed task. The card
> should therefore not be treated as an approved agent identity.

# 11. A2A request identity limitation

A2A v1.0's standardized JWS protects the Agent Card.

It does not, by itself, create a per-request signature over every message body.

For each incident also preserve:

```text
OAuth token metadata
mTLS identity/certificate
HTTP/gRPC peer identity
request/response body hashes
A2A-Version
A2A-Extensions
tenant
task ID
context ID
message ID
transport request IDs
```

Do not infer request authenticity from Agent Card signature alone.
