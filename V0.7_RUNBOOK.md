# AI-DFIR Analyst Workbench v0.7

## Purpose

v0.7 turns the v0.1–v0.6 model-integrity, activation, fleet, provenance, containment, and recovery capabilities into one analyst-facing workspace.

The workbench is intentionally **read-only** against case evidence.

Its core rule is:

> Missing evidence is unknown. Missing evidence is never automatically interpreted as clean evidence.

## What the workbench shows

- case severity and correlation confidence
- evidence-coverage score and missing-evidence categories
- model/layer activation divergence heatmap
- matched approved-vs-suspect activation geometry
- changed tensors and low-rank/SVD screening results
- runtime hooks/adapters and inventory findings
- captured fleet state and fleet alerts
- delegated-authority / agent / tool / consequence graph
- open downstream consequences
- containment status and containment audit history
- evidence-chain/package-integrity verification
- normalized forensic timeline
- signed analyst annotations
- deterministic investigator report
- case-wide evidence search with file SHA-256 provenance

# 2. Start the workbench

For a directory containing one or more AI-DFIR cases:

```bash
python analyst_dashboard.py \
  --case-root /evidence \
  --host 127.0.0.1 \
  --port 8877
```

Open:

```text
http://127.0.0.1:8877
```

The server automatically discovers supported case artifacts underneath the case root.

## Security note

The built-in server deliberately has no user-authentication system.

Default binding is therefore:

```text
127.0.0.1
```

Do **not** expose it directly to an untrusted network.

For remote analyst access use an authenticated reverse proxy, VPN, SSH tunnel, or equivalent enterprise control.

# 3. Read-only guarantees

The dashboard implements:

```text
GET        allowed
POST       405
PUT        405
DELETE     405
```

The UI does not write annotations, containment actions, or evidence changes.

That separation is intentional:

```text
source evidence
     |
     +---- read-only dashboard
     |
     +---- separate signed annotation log
```

An analyst browsing a case should not contaminate it.

# 5. Activation divergence heatmap

The workbench consumes:

```text
anomaly_events.csv
matched_activation_delta.csv
```

and visualizes each observed residual depth.

The heatmap combines:

```text
maximum absolute robust-z
anomaly status
matched activation cosine
relative L2 divergence
```

The dashboard does not impose a new universal threshold. It visualizes the thresholding already produced by the approved-baseline engine.

A low-dimensional delta is a forensic signal to correlate, not standalone proof of abliteration.

# 10. Open consequences

The workbench consumes:

```text

```

and shows downstream effects that remain unresolved after model containment.

Examples:

```text
account disabled

```

# 11. Evidence integrity

The workbench verifies evidence where enough metadata exists.

Currently supported in the UI:

```text
package manifests
containment audit hash chains
```

It reports:

```text
PASS
FAIL
MISSING / no verification artifact
```

It does not convert absence of a verification artifact into PASS.

# 12. Forensic timeline

The workbench prefers:



# 14. Signed analyst annotations

Analyst notes are intentionally stored **outside the source evidence objects**.

Create an analyst identity:

```bash
python fleet_crypto.py keygen \
  --private analyst.pem \
  --public analyst.pub.pem
```

Add a note:

```bash
python analyst_annotations.py add \
  --log /evidence/CASE-001/annotations.jsonl \
  --private-key analyst.pem \
  --case-id CASE-001 \
  --author examiner@example \
  --note "Runtime hook aligns with the first material activation divergence." \
  --evidence-ref 01_runtime/runtime_findings.json \
  --tag mechanistic-correlation
```

Verify the annotation chain:

```bash
python analyst_annotations.py verify \
  --log /evidence/CASE-001/annotations.jsonl \
  --public-key analyst.pub.pem
```

Each annotation is:

```text
Ed25519 signed
hash chained
case bound
time stamped
evidence-reference capable
tagged
```

The workbench displays these annotations but does not create or edit them.

# 16. Evidence interpretation

Recommended wording remains conservative.

Avoid:

> The model was abliterated because it answered an unsafe prompt.

Prefer:

> The deployed AI execution materially diverged from the approved baseline beginning at residual depth X. The divergence correlates with [checkpoint/runtime/adapter] evidence and [timeline/provenance] evidence. The combined evidence supports a Level N model-integrity finding.

Only attribute the exact modification technique when multiple independent evidence sources support it.
