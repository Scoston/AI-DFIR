# AI-DFIR v0.8 — Universal Evidence Layer Runbook

## 1. List evidence packs

```bash
python evidence_pack_engine.py catalog
```

## 2. Resolve a Microsoft alert

```bash
python evidence_pack_engine.py resolve \
  --alert-id AI.Azure_ASCIISmuggling
```

## 3. Resolve a local Defender alert for Claude Code

```bash
python evidence_pack_engine.py resolve \
  --alert-title "Suspicious AI prompt injection" \
  --agent "Claude Code"
```

The Microsoft Defender Endpoint pack provides Defender/endpoint requirements. The related Claude Code pack provides the vendor-native transcript, history, settings, MCP, hook, file-history, and application-state evidence.

## 4. Attach an evidence pack to a case

```bash
python evidence_pack_engine.py profile \
  --case /evidence/CASE-001 \
  --pack anthropic.claude_code.prompt_injection \
  --alert-title "Suspicious AI prompt injection" \
  --agent "Claude Code"
```

This writes `incident_profile.json`.

## 5. Assess evidence sufficiency

```bash
python evidence_pack_engine.py assess \
  --pack anthropic.claude_code.prompt_injection \
  --case /evidence/CASE-001 \
  --out /evidence/CASE-001/evidence_assessment.json \
  --markdown /evidence/CASE-001/evidence_assessment.md
```

The result distinguishes:

```text
PRESENT
MISSING
mandatory
conditional
conclusion supported/not-supported
```

`not_supported` means the required evidence for that conclusion is not present. It does not mean the underlying incident did or did not occur.

## 6. Generate acquisition guidance

```bash
python evidence_acquisition_plan.py \
  --pack microsoft.AI.Azure_AnomalousToolInvocation \
  --out acquisition_plan.md
```

Microsoft packs also include Advanced Hunting starter queries for:

```text
AlertInfo
AlertEvidence
CloudAppEvents
AgentsInfo
BehaviorInfo
BehaviorEntities
DeviceProcessEvents / DeviceFileEvents / DeviceNetworkEvents
```

Replace placeholders and constrain the investigation time window.

## 7. Claude Code prompt-injection minimum evidence

The built-in pack requests, at minimum:

```text
~/.claude/projects/<project>/<session-id>.jsonl
~/.claude/history.jsonl
~/.claude/projects/<project>/<session>/tool-results/
CLAUDE.md / CLAUDE.local.md
~/.claude/settings.json
.claude/settings.json
.claude/settings.local.json
managed settings
~/.claude.json
.mcp.json
hook configuration/scripts
endpoint process/file/network telemetry
```

Conditional evidence includes file-history snapshots, skills/agents/rules/memory, plans/tasks/debug files, paste/image caches, session environment, Git evidence, and enterprise/provider audit.

Claude's transcript/history absence must not be treated as no activity because retention, custom config directory, or disabled session persistence can remove/prevent those files.

## 8. Microsoft Defender for Cloud AI catalog

`MICROSOFT_AI_ALERT_CATALOG.json` contains every alert currently enumerated on Microsoft's AI workload alert page, each mapped to its own evidence pack.

This includes credential theft, Prompt Shields jailbreak detections, malicious/phishing URLs, suspicious access, ASCII smuggling, denial-of-wallet patterns, access anomalies, service-principal initial access, anomalous tool invocation, LLM reconnaissance, malicious uploaded models, and the AI-related exposed Kubernetes service alert.

## 9. Agent 365

The Agent 365 pack requests:

```text
AlertInfo
AlertEvidence
CloudAppEvents
AgentsInfo
BehaviorInfo
BehaviorEntities
prompt evidence when enabled
full tool invocation sequence
knowledge/retrieval evidence when used
identity and target-system evidence
```

Microsoft currently documents the detection families rather than a stable exact alert-ID catalog for each family. v0.8 intentionally does not invent IDs.

## 10. Purview / Claude Enterprise

The Purview pack requests Unified Audit Log AI interactions, DSPM Activity Explorer events, prompts/responses, referenced files, sensitivity/DLP/SIT evidence, and identity context. This can provide an independent cloud-side copy of Claude Enterprise AI interactions where Purview collection is configured.

## 11. Universal provider adapters

```bash
python universal_provider_adapter.py --model "Qwen"
python universal_provider_adapter.py --model "Claude Code"
python universal_provider_adapter.py --model "Azure OpenAI"
```

The registry declares which evidence types are supported, unavailable, or provider/application dependent.

## 12. Analyst workbench

The v0.8 workbench adds an **Incident Evidence Pack & Conclusion Sufficiency** panel. It shows:

- mandatory evidence percentage
- missing mandatory/conditional evidence
- likely native artifact locations
- why each artifact matters
- conclusion gates and missing prerequisites

The dashboard remains read-only.

## 13. Create your own pack

Copy an existing JSON file in `evidence_packs/`, change the ID/match rules/artifacts/gates, and validate it with the self-test or `evidence_pack_engine.py catalog`. No engine modification is required.
