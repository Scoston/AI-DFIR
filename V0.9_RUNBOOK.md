# AI-DFIR v0.9 — Agentic Incident Response

## Purpose

v0.9 extends the Universal Evidence Layer into agentic systems where incidents
can originate outside the model itself.

The forensic domains are:

```text
MODEL
AGENT
IDENTITY
AUTHORITY
MEMORY
RAG / CONTEXT
MCP / TOOLS
INTER-AGENT MESSAGING
ORCHESTRATION / TASKS
HUMAN APPROVAL
DOWNSTREAM CONSEQUENCES
```

A model can be cryptographically pristine while the effective AI system is compromised.

Use `agentic_trace_v2.py` to normalize evidence from different agent frameworks:

```text
human_input
model_input
model_output
retrieval_query
retrieval_result
memory_read/write/update/delete
tool_discovery

mcp_request/response
delegation
agent_message
approval_request/decision
identity_issue/use
policy_decision
code_execution
network_action
data_access/write
consequence

```

Every event supports:

```text
event_id

cause_event_ids        -> explicit evidentiary cause
correlation_ids        -> association only
actor_id
target_id
authority_id
session_id
trace_id

metadata
```

**Rule:** correlation or timestamp proximity is not promoted to causation.

Validate a normalized event export:

```bash
python agentic_trace_v2.py validate \
  --file agentic_events.jsonl
```

## 2. MCP forensics

MCP's current 2026-07-28 specification uses a stateless protocol core and adds
header-based routing, cacheable list results, authorization hardening and a
formal Tasks extension.

Preserve:

```text
server identity
server endpoint
protocol version
tools/list
prompts/list
resources/list
resources/read
Mcp-Method
Mcp-Name
tools/call
Tasks lifecycle
authorization issuer
client identity/metadata
catalog cache TTL/scope
gateway / WAF / proxy telemetry
downstream target-system audit
```

Normalize an inventory:

```bash
python mcp_forensics.py inventory \
  --input current_mcp_inventory.json \
  --out normalized_mcp_inventory.json
```

Compare approved vs suspect:

```bash
python mcp_forensics.py diff \
  --approved approved_mcp.json \
  --suspect suspect_mcp.json \
  --out mcp_findings.json
```

Analyze request logs:

```bash
python mcp_forensics.py logs \
  --log mcp_gateway.jsonl \
  --out mcp_analysis.json
```

Findings include:

```text
unexpected_mcp_server
unexpected_mcp_tool
mcp_tool_schema_changed
mcp_authorization_issuer_changed
mcp_client_id_changed
```

The analyzer never calls an MCP tool.

## 3. RAG / context poisoning

Create an approved and suspect corpus manifest containing document IDs/URIs,
content SHA-256, ACL hash and metadata hash.

Compare:

```bash
python rag_forensics.py diff \
  --approved approved_corpus.json \
  --suspect suspect_corpus.json \
  --out rag_findings.json
```

Then determine which sessions actually consumed a known poisoned chunk:

```bash
python rag_forensics.py trace \
  --events agentic_events.jsonl \
  --poisoned-hash <CHUNK_SHA256> \
  --out rag_provenance.json
```

The report distinguishes:

```text
poisoned document exists
        !=
poisoned chunk retrieved
        !=
poisoned chunk entered model context
        !=
poisoned context caused a tool action
        !=
tool action produced impact
```

## 5. Effective authority

Authority is not simply the agent's nominal role.

v0.9 computes authority from:

```text
direct scopes
roles
delegations
tool requirements
approval policies
```

Compute:

```bash
python authority_engine.py compute \
  --input suspect_authority.json \
  --out effective_authority.json
```

Compare:

```bash
python authority_engine.py diff \
  --approved approved_authority.json \
  --suspect suspect_authority.json \
  --out authority_diff.json
```

Potential findings:

```text
effective_authority_expanded
new_tool_reachability
```

A new reachable destructive tool is evidence of an expanded attack surface even
when it was never used.

## 6. Multi-agent causal reconstruction

```bash
python agentic_graph.py \
  --events agentic_events.jsonl \
  --seed <SUSPECT_ROOT_EVENT_ID> \
  --out causal_analysis.json
```

The graph uses only:

```text
parent_event_id
cause_event_ids
```

for causal edges.

`correlation_ids` are displayed but never used to claim causation.

This allows a report such as:

```text
poisoned RAG chunk
  -> agent A model input
  -> delegation to agent B
  -> tool call
  -> API result
  -> consequence
```

only when those links are explicitly present.

## 9. Agentic rule engine

Run:

```bash
python agentic_rules.py \
  --input mcp_findings.json \
  --input authority_diff.json \
  --input memory_lineage.json \
  --input agentic_events.jsonl \
  --out agentic_rule_findings.json
```

Rules are deterministic JSON conditions over normalized signal names/event types.
There is no `eval` or model-generated executable logic.

Findings map to:

```text
OWASP Agentic risk
MITRE ATLAS technique name(s)
secondary evidence pack
```

They are triage/correlation findings, not proof by themselves.

## 14. MCP version sensitivity

The MCP specification changed materially in 2026.

Preserve the actual protocol version in every MCP case.

Do not infer current behavior from an old MCP deployment.

In particular, the 2026-07-28 release introduced a stateless core, changed
authorization expectations, formalized extensions, and changed Tasks/legacy
transport behavior.

## 15. Investigation principle

A full agentic incident should distinguish:

```text
COMPONENT PRESENT
COMPONENT CHANGED
COMPONENT USED
ACTION OCCURRED
ACTION CAUSED CONSEQUENCE
```

These are five different evidentiary propositions.

The tool must not collapse them into one.
